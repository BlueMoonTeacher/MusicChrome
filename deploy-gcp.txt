GCS 정적 웹 호스팅 (계획 1번) — 배포 절차 요약

전제: gcloud CLI 설치 및 로그인(gcloud auth login), 결제가 활성화된 GCP 프로젝트.

1) 버킷 생성 (이름은 전역 유일, 예: my-school-piano)
   gsutil mb -l asia-northeast3 gs://YOUR_BUCKET_NAME

2) 웹사이트로 설정 (메인 문서)
   gsutil web set -m index.html -e index.html gs://YOUR_BUCKET_NAME

3) 파일 업로드 (이 폴더에서)
   gsutil cp index.html piano.html styles.css app.js gs://YOUR_BUCKET_NAME/

4) 전체 읽기 공개 (정적 웹용)
   gsutil iam ch allUsers:objectViewer gs://YOUR_BUCKET_NAME

5) 접속 URL
   http://storage.googleapis.com/YOUR_BUCKET_NAME/index.html
   (또는 콘솔의 Cloud Storage > 버킷 > 웹사이트 구성에 표시된 엔드포인트)

HTTPS가 필요하면 Load Balancer + 인증서 또는 Cloud CDN을 콘솔에서 추가로 구성합니다.
학교망에서는 443(HTTPS)만 허용되는 경우가 많아, 최종 URL은 HTTPS로 제공하는 구성을 권장합니다.

참고: https://cloud.google.com/storage/docs/hosting-static-website

https://storage.googleapis.com/student-insight-bridge-musicchrome-piano/index.html
https://storage.googleapis.com/student-insight-bridge-musicchrome-piano/piano.html
(캐시 때문에 예전 화면이면 뒤에 ?t=1 처럼 아무 숫자나 붙여서 열기, 또는 piano.html 사용)

※ insight-app-....run.app (백동초 Insight) 는 다른 서비스입니다.

최신 배포 확인: 브라우저 탭 제목이 "터치 피아노 · 2026 04 14 - 0000" 형식이고,
맨 위 도구줄 왼쪽 빌드 배지·녹색 상태줄 문구가 "2026 04 14 - 0000"과 일치하는지 보면 됩니다.
(배포할 때마다 app.js의 BUILD_DISPLAY와 HTML 빌드 문구를 같은 시각으로 맞추세요.)
(옥타브 버튼 아래 녹색 상태줄에도 동일 빌드 번호가 있습니다.)
Chrome: F12 → Network → Disable cache 체크 후 새로고침.

--- GitHub Actions 자동 배포 (CI가 실패할 때) ---
워크플로는 시크릿 이름이 정확히 GCP_SA_KEY_B64 일 때만 동작합니다.
(예전 이름 GCP_SA_KEY 만 넣었으면 비어 있다고 나옵니다. 이름을 바꿔 새로 등록하세요.)

1) GCP 콘솔 → IAM → 서비스 계정 → 키 → JSON 추가·다운로드
2) PowerShell (키 파일 경로에 맞게):
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\경로\키파일.json"))
3) 출력 문자열 전체를 복사 (앞뒤 따옴표 없이)
4) GitHub → 해당 저장소 → Settings → Secrets and variables → Actions
   → Repository secrets → New repository secret
   Name:  GCP_SA_KEY_B64
   Secret: (위 Base64 붙여넣기)

저장 후 Actions 탭에서 실패한 워크플로 → Re-run jobs.
